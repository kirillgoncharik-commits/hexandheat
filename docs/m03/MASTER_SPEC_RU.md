# Hex and Heat M03 Спецификация визуального среза

Дата 30 октября 2026. Владелец продукта Кирилл Гончарик. Задача [#19](https://github.com/kirillgoncharik-commits/hexandheat/issues/19).

## Решение и границы этапа

M03 возобновляет разработку на базе кода PR #18 `20ffb0d8d64216da21bd580056ba16c83434ac3d`. `main` содержит только README; PR #13, #14, #16 и #18 остаются открытыми. Это первый оформленный вертикальный срез и подготовка к запуску, не готовый к публикации слот. Ставки в preview используют только тестовый баланс и детерминированные fixtures.

По прямому указанию владельца продукта от 30 октября видео заменяется растровой последовательностью с будущим переходом на Spine. Разрешены первая итерация графики, макеты всех экранов, код главного экрана и документация. Это разрешение заменяет более ранний запрет на начало чернового арта; не разрешает покупки, принятие коммерческих условий, real-money play или Stake submission. Новый этап основан на верхушке stack PR #18, чтобы сохранить готовый код. Старые PR не сливаются автоматически.

Результаты M03: полный screen/content contract; Figma journey и layouts; рабочая оформленная основная сцена; 20 raster кадров ведьмы, 12 предметных ассетов и фон; architecture/compliance gap register; задание M04. Детальные требования хранятся здесь и в `design/screen-map.json`. Обнаруженные расхождения Figma фиксируются в отчёте, а не считаются выполненными по одному факту генерации.

## Состояние исходной разработки

Проверено по GitHub и локальной копии: PR #14 даёт функциональный прототип 6×5; PR #16 добавляет CSS dance loops; PR #18 добавляет SDK pins, adapter официального формата, 6 sample books, локальный RGS, replay прошлого локального раунда, временный audio/video POC. Исходный набор проверок воспроизведён: 3 документационных + 14 math/replay + 22 JS = 39. Эти проверки подтверждают прототип, но не production RTP, live RGS, отсутствие рисков или сертификацию.

Free Spins сейчас отсутствует в domain validator и production books. CSS времена 4.2/3.6/4.8 секунды и промежуточные IDLE seams заменяются едиными 4000 мс. Материал PR #18 полезен, но его выражение SDK integration нельзя трактовать как готовый официальный production-клиент.

## Зафиксированная механика

Поле состоит из 6 колонок и 5 строк. Scatter Pays считает одинаковые обычные символы в любых позициях. В действующей гипотезе от 8 одинаковых символов; thresholds и выплаты должны быть утверждены математиком. Выплаченные позиции исчезают одновременно, остальные падают по колонкам; новые символы и следующая оценка приходят из outcome book.

Potion увеличивает видимый множитель котла. Множитель начинается с ×1 и не переносится между независимыми ставками. UI показывает текущую выплату каскада, накопленный win и окончательный win раздельно; значения получают из RGS events. Ведьма и FX ничего не рассчитывают. Финал раунда не ждёт окончания декоративного танца.

Полный MVP включает один Free Spins feature внутри одной оплаченной книги. Количество спинов, retrigger, значения Potion, поведение множителя между бесплатными спинами, max win и RTP пока требуют math sign-off. Ни второй bonus, ни bonus buy, ни jackpot/gamble/cashout не добавляются. При утверждении Free Spins отдельно решить, сохраняется ли множитель только внутри каждого free spin или внутри всего bonus book; эта семантика должна совпадать в math, events, rules и UI.

## Пользовательские маршруты

Обычный вход: S01 → S02 → S03 → S04 при выборе ставки → S05 → S06. Выигрыш: S07 → S08 при Potion → S09 → повторная оценка → S10. Проигрыш: S06 → S10 с нулём, без победной реакции. S11/S12 оформляют действительный итог, затем S03. Free Spins: S13 → S14 → S15 если событие существует → S14 → S16 → S03. Ставка списывается один раз на исходный раунд.

Окна S19–S21 доступны из idle и по безопасной политике во время presentation. Они не создают ставку; Space внутри окна не запускает игру. Autoplay S17/S18 условный: реализовывать только вместе с явным подтверждением и Stop. Если feature исключён из релиза, убрать его целиком из макетов, rules и content, а не оставлять мёртвую кнопку.

При ambiguous timeout после play нельзя повторять списание. Вход через S23 → re-auth → S25 восстанавливает исходный book. Сессия с истёкшим токеном ведёт в S24; ограничения юрисдикции в S30. Ошибка графики включает статичный fallback и не меняет финансовый lifecycle.

Публичный replay имеет отдельный вход S26 → S27 → S28 → Play Again. S29 обслуживает 404 и ошибочные параметры. Ни session, ни auth, ни play/end-round не используются; нет пути в обычные ставки. Существующий Replay last в прототипе демонстрирует сохранённый локальный outcome и не заменяет этот полный маршрут.

## Контракт экранов и контента

Обозначения runtime: implemented означает реализацию в прототипе, partial означает часть поведения, layout означает макет/спецификацию. Никакой layout сам по себе не закрывает релизный gate. Все экраны должны иметь desktop вариант и адаптивное правило; основные mobile варианты и popout обязательно визуально проверить.

### S01 Loading

Вход: Вход в iframe.

Контент: Название игры, прогресс обязательных ассетов, mute, текст ошибки загрузки.

Действия: Дождаться загрузки; повторить только ассеты. Следующий экран: S02. Ошибки: S23. Тип: platform. Runtime: layout.

### S02 Welcome

Вход: Первая загрузка.

Контент: Три правила: сбор одинаковых символов, каскады, котёл внутри раунда; Continue; доступ к правилам.

Действия: Continue не делает ставку. Следующий экран: S03. Ошибки: S23. Тип: product. Runtime: layout.

### S03 Base idle

Вход: Успешная авторизация и нет активного раунда.

Контент: Поле 6×5, баланс, выбранная ставка, итог прошлого раунда, котёл ×1, Spin, info, Settings, Fast, Replay.

Действия: Spin или Space; менять ставку; открыть окна. Следующий экран: S04, S05, S19, S20, S21, S17. Ошибки: S22, S24. Тип: platform. Runtime: implemented.

### S04 Bet picker

Вход: Нажатие на сумму.

Контент: Все уровни из auth, текущая сумма, валюта, min/max/step, подтверждение и Cancel.

Действия: Выбор без отправки play; блокировка при активном раунде. Следующий экран: S03. Ошибки: S22. Тип: platform. Runtime: implemented.

### S05 Request pending

Вход: Spin после локальных preflight проверок.

Контент: Поле остаётся; индикатор ожидания; заблокированы Spin и ставка.

Действия: Одна отправка; повторный Space игнорируется. Следующий экран: S06. Ошибки: S23, S24, S30. Тип: architecture. Runtime: implemented.

### S06 Reveal

Вход: Принят валидный outcome.

Контент: Тридцать символов; новая цепочка; котёл ×1; round win 0; корректный mode.

Действия: Без ставок до settlement. Следующий экран: S07, S10. Ошибки: S23. Тип: product. Runtime: implemented.

### S07 Symbol win

Вход: win event.

Контент: Все выигравшие позиции, выплата текущего каскада отдельно от accumulated total, валюта, активный множитель.

Действия: Дождаться читаемого подсвечивания. Следующий экран: S08, S09, S10. Ошибки: S23. Тип: platform. Runtime: partial.

### S08 Potion increment

Вход: multiplier event.

Контент: Флакон, старый множитель, приращение, новый множитель; отдельный FX, без ложного BONUS.

Действия: Продолжить timeline; числовое значение только из события. Следующий экран: S09. Ошибки: S23. Тип: product. Runtime: implemented.

### S09 Cascade

Вход: Следующая board snapshot.

Контент: Удаление выплаченных символов, падение по колонкам, новые символы, номер каскада.

Действия: Не сбрасывать накопленный выигрыш или ведьму. Следующий экран: S07, S10. Ошибки: S23. Тип: product. Runtime: partial.

### S10 Final result

Вход: finalWin и settlement.

Контент: Точная окончательная сумма; при нуле спокойное состояние; новая ставка только после подтверждения RGS.

Действия: Возврат в idle; сохранять итог на экране. Следующий экран: S03, S11, S12, S13. Ошибки: S23. Тип: platform. Runtime: implemented.

### S11 Big win

Вход: Presentation tier на реальном выигрыше.

Контент: Сумма, название tier, прогресс count-up, Continue; точный финал доступен.

Действия: Пропуск сокращает оформление, не settlement. Следующий экран: S03. Ошибки: S23. Тип: product. Runtime: layout.

### S12 Max win

Вход: Явный cap event утверждённой математики.

Контент: Max win reached, точная сумма и лимит режима, сообщение об окончании bonus если применимо.

Действия: Без обещания следующего бонуса или gamble. Следующий экран: S03. Ошибки: S23. Тип: product. Runtime: layout.

### S13 Free Spins awarded

Вход: bonusStart в одном outcome book.

Контент: Число бесплатных спинов из события, trigger symbols, правила множителя, Start.

Действия: Start продолжает уже купленный раунд, не play. Следующий экран: S14. Ошибки: S23. Тип: product. Runtime: layout.

### S14 Free Spins active

Вход: Внутри bonus book.

Контент: Осталось/всего, bonus total и current spin win отдельно, multiplier, режим; ставка зафиксирована.

Действия: Переход между spin events, без списания новых ставок. Следующий экран: S15, S16. Ошибки: S23, S25. Тип: product. Runtime: layout.

### S15 Free Spins retrigger

Вход: Явное событие retrigger.

Контент: Сколько добавлено и новый остаток; условия из утверждённых правил.

Действия: Продолжение того же bonus book. Следующий экран: S14. Ошибки: S23. Тип: conditional. Runtime: layout.

### S16 Bonus summary

Вход: bonusEnd и финальный итог.

Контент: Bonus total, spins played, точная сумма, Continue; settlement единожды.

Действия: Возврат в base idle после settlement. Следующий экран: S03. Ошибки: S23. Тип: product. Runtime: layout.

### S17 Autoplay setup

Вход: Пользователь открыл autoplay.

Контент: Количество раундов, ставка, итоговая плановая стоимость, Stop условия, Confirm и Cancel; никакого запуска одним открытием.

Действия: Confirm запускает выбранный план; не бессрочный режим. Следующий экран: S18, S03. Ошибки: S22. Тип: conditional. Runtime: layout.

### S18 Autoplay running

Вход: Явное подтверждение.

Контент: Осталось раундов, текущие деньги и win, всегда доступный Stop.

Действия: Stop отменяет будущие ставки; текущую завершить. Следующий экран: S03, S18. Ошибки: S22, S23, S24. Тип: conditional. Runtime: layout.

### S19 Settings

Вход: Кнопка Settings.

Контент: Mute, music, SFX, Fast, reduced motion, Close; сохранить локальные настройки.

Действия: Escape/Close возвращают фокус; Space не ставит при открытом окне. Следующий экран: S03. Ошибки: S23. Тип: platform. Runtime: partial.

### S20 Rules and UI guide

Вход: Info.

Контент: Все правила и границы раунда; кнопки; server-authoritative result; connectivity/resume; disclaimer.

Действия: Вкладки rules/paytable; Close; текст прокручивается внутри окна. Следующий экран: S03, S21. Ошибки: S23. Тип: platform. Runtime: partial.

### S21 Paytable

Вход: Info paytable.

Контент: Все symbol tiers/thresholds/payouts, Potion значения, Scatter trigger/retrigger, RTP, max win и cost каждого режима.

Действия: Все числа берутся из versioned rules-content; до approval в дизайн-файле TBD. Следующий экран: S20, S03. Ошибки: S23. Тип: platform. Runtime: layout.

### S22 Insufficient balance

Вход: Preflight либо ERR_IPB.

Контент: Недостаточно средств, баланс/стоимость, Close или уменьшить ставку; не списывать повторно.

Действия: Возвращает выбор ставки; пополнение принадлежит оболочке оператора. Следующий экран: S04, S03. Ошибки: S24. Тип: platform. Runtime: partial.

### S23 Network or assets error

Вход: Timeout/decode/API error.

Контент: Понятный текст; отличать до outcome от неизвестного результата play; безопасный Retry; запрошенный ID в redacted diagnostic.

Действия: После ambiguous play только re-auth/reconcile, не повторять play. Следующий экран: S25, S01. Ошибки: S24. Тип: architecture. Runtime: layout.

### S24 Session expired

Вход: ERR_IS или ERR_ATE.

Контент: Session expired; Relaunch via casino; повторная ставка заблокирована.

Действия: Релонч через оператора; не создавать фальшивую локальную сессию. Следующий экран: S01. Ошибки: S30. Тип: platform. Runtime: layout.

### S25 Resume active round

Вход: auth вернул active round.

Контент: Восстановленная ставка, mode, состояние книги, продолжить с event cursor; никакой второй оплаты.

Действия: Один authoritative book; /bet/event checkpoints; settle один раз. Следующий экран: S06, S14, S10. Ошибки: S23. Тип: platform. Runtime: layout.

### S26 Replay loading and ready

Вход: replay=true отдельная точка входа.

Контент: Загрузка replay; оригинальная ставка, cost multiplier и реальная стоимость; Play после загрузки.

Действия: GET replay без session/auth; без balance/bet/autoplay. Следующий экран: S27. Ошибки: S29. Тип: platform. Runtime: layout.

### S27 Replay playing

Вход: Play replay.

Контент: Та же цепочка событий, win, multiplier, исходная стоимость, индикатор Replay.

Действия: Не совершать wallet/play/end-round; нельзя перейти к обычным ставкам. Следующий экран: S28. Ошибки: S29. Тип: platform. Runtime: layout.

### S28 Replay result

Вход: Конец replay.

Контент: Финал, первоначальная base ставка, mode cost multiplier, фактическая стоимость, Play Again.

Действия: Повтор только воспроизведения. Следующий экран: S27. Ошибки: S29. Тип: platform. Runtime: layout.

### S29 Replay unavailable

Вход: 404 или некорректные параметры.

Контент: Replay unavailable, понятная причина без внутренних данных, Retry только GET.

Действия: Никакой автоматической авторизации или перехода к ставкам. Следующий экран: S26. Ошибки: S29. Тип: platform. Runtime: layout.

### S30 Jurisdiction restriction

Вход: ERR_LOC/ERR_GLE/operator restriction.

Контент: Игра недоступна / достигнут лимит; безопасный выход к оператору.

Действия: Не обходить ограничение; не fallback на mock. Следующий экран: S01. Ошибки: нет. Тип: platform. Runtime: layout.

## Контент и локализация

Запускать EN как базовый словарь, RU как контрольный длинный текст; фактический список языков уточнить в Studio. Идентификаторы строк и rules-content version хранятся отдельно от разметки. Числа RTP, paytable, max win, feature trigger и все obtainable values экспортируются из утверждённой math configuration, не вводятся дизайнером. До этого в Figma используется TBD; в preview видна честная пометка об отсутствии утверждённой математики. Production build должен завершаться ошибкой при незаполненном обязательном контенте.

Валюты форматируются с учётом locale и требуемой точности выигрышей. Баланс может иметь 2 знака, но sub-cent win не должен стать нулём: например 0.1× от $0.01 = $0.001. Отдельный social словарь и запретные слова проверяются по актуальной таблице Stake; нельзя считать простую замену Bet → Play полным соответствием. Юрисдикционная таблица не была доступна полностью через публичный текст, поэтому sign-off остаётся открытым.

Rules включают UI guide и смысл общего disclaimer: сбой аннулирует игру/выигрыши, требуется связь, после разрыва нужно закончить незавершённый раунд; ожидаемый возврат относится к множеству игр, отображение иллюстративно, окончательный результат определён RGS. Окончательный текст и правовую строку сверить с текущим шаблоном Engine перед submission.

## Макеты и визуальная система

Desktop frame 1440×900: title/header сверху, центральное поле слева, ведьма и котёл справа, нижняя панель balance/bet/win/Spin. Mobile 390×844 и 360×640: сетка сохраняет 6×5 без деформации; компактная ведьма и котёл под полем; управление снизу. Popout 480×320 используется как внутренний тестовый размер; точный размер операторского Popout S нужно проверить в Studio. На компактном размере декор сокращается первым. Сумма, ставка, multiplier и ввод остаются читаемыми. Safe-area обязательны.

Палитра: void #120D18, plum #2A1833, copper #B66A3C, ember #FF9A3C, jade #70E0A2, parchment #E7D8C4. Touch targets минимум 44 CSS px - внутренний UX критерий. Основной текст 14px, цифры tabular. Тени и textures подчинены силуэту символа. Цвет не единственный носитель смысла. Portrait/fullscreen/rotate/200% zoom входят в QA.

Figma структура: 00 Journey, 01 Desktop, 02 Mobile and Popout, 03 Style and Assets, 04 Content and State Specs. На free-плане допустимы секции одной страницы. Названия включают S-ID, viewport, state. Макеты должны оставаться редактируемыми; PNG может быть asset fill, но не полной заменой слоёв интерфейса. Journey включает стрелки и подписи условий; ссылки прототипа проверяются отдельно. Компоненты: SymbolCell, Board, Cauldron, Amount, SpinButton, Modal, Toast, SettingRow. Варианты: idle/disabled/win/error/replay, normal/social, desktop/mobile/compact.

## Приёмка M03

1. Документы явно показывают текущий код, проектные решения, непроверенные требования и blockers. Все S01–S30 покрыты контентом и переходами.
2. Основной экран запускается и содержит все 30 клеток, первую графику, bet/balance/win, котёл, Spin, Fast, replay, Settings и rules.
3. Каждому witch state соответствует ровно 4 растровых файла; полный цикл 4000ms. Переход tier только на конце цикла. Ошибка изображения и reduced motion не блокируют раунд.
4. Новые проверки не ломают старые. Math и wallet не меняются художественными доработками.
5. Figma принят только после визуальной проверки фактических экранов. Непостроенные/ошибочные части перечислить в отчёте. Наличие файла или ответа агента не считается доказательством.
6. M04 имеет отдельные outputs, blockers, owner и проверки. Stake submission остаётся закрыт до выполнения.
