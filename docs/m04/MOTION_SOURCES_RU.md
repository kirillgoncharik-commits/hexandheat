# Источники движения и воспроизводимость

Дата проверки источников: 02.11.2026. Статус: **референсные движения для сравнения и переноса; художественная приёмка открыта**.

## Происхождение

Использованы реальные записи [CMU Graphics Lab Motion Capture Database](https://mocap.cs.cmu.edu/), конвертированные Bruce Hahn в MotionBuilder-friendly BVH и сохранённые в [зеркале una-dinosauria/cmu-mocap](https://github.com/una-dinosauria/cmu-mocap). CMU ссылается на конверсию Hahn в разделе [Resources](https://mocap.cs.cmu.edu/resources.php). Коммит зеркала закреплён: `09a07f54f3bbb58797325f009282d0b2048a2871`.

Описания и частоты выбранных записей проверены по первичным каталогам [subject 05](https://mocap.cs.cmu.edu/search.php?subjectnumber=05) и [subject 49](https://mocap.cs.cmu.edu/search.php?subjectnumber=49). Во всех трёх выбранных исходниках номинальная частота120Hz, в BVH записано `Frame Time: .0083333`. Сэмплирование выполняется по этому времени, а не по предположению о30FPS исходника.

Для49_12 выбран более непрерывный жест с опусканием/раскрытием рук и наклоном корпуса. Ранее исследованный49_22 оказался преимущественно удержанием баланса и не вошёл в поставляемые три JSON.05_12 сохраняет асимметрию рук, но содержит удержание позы. Ни один кандидат сам по себе не доказывает качество финального обворожительного танца.

## Что именно подготовлено

В `apps/web/assets/witch/reference-cycle/*-manikin.json` находятся121 отсчёт на четырёхсекундный цикл при30Hz, включая обе границы.31 именованный сустав имеет имя и индекс родителя. Координаты — правосторонние, Y вверх, относительно Hips в каждом кадре, нормализованы по высоте персонажа в установочной позе источника. Отдельный `rootTrack` сохраняет перемещение корня относительно начала окна.

- `frames`, `rootTrack`: выбранный исходный четырёхсекундный фрагмент.
- `loopFrames`, `loopRootTrack`: явно производная петля для сравнения.
- `source`, `sampling`, `loopCorrection`: URL, коммит, хеш, исходная частота, точное окно и метод обработки.
- `metrics`: сохранённые результаты исследования окон/стыка; они не являются художественной оценкой или повторно измеренным результатом каждой регенерации.

Парсер соблюдает порядок каналов BVH. Локальные переносы интерполируются линейно, локальные вращения — shortest-arc quaternion SLERP; затем выполняется forward kinematics. Это не копирование трёхмерных Euler-углов в2D.

Петля использует нахлёст0.4s: конец фрагмента смешивается с его началом в локальных трансформациях с quintic smoothstep. Получается естественный цикл3.6s, который воспроизводится со скоростью0.9× до длительности4s. Начальная фаза соответствует `cropStart+0.4s`. Длины сегментов сохраняются с численной точностью. Точное совпадение конечной позы не подтверждает идеальную непрерывность скорости.

## Воспроизведение

Пакеты Python не требуются. Исходные BVH по умолчанию хранятся в игнорируемой папке `assets/raw/cmu-motion/`; альтернативу задаёт `--source-dir`.

```bash
python3 tools/motion/bvh_motion.py
python3 tools/motion/prepare_reference_motions.py --source-dir /path/to/pinned-bvh-files --check
```

Первая команда проверяет порядок каналов, FK, End Sites, интерполяцию через границу±180° и порядок перемешанных rotation/translation каналов. Вторая восстанавливает все отсчёты и сравнивает точные байты/хеши с текущими JSON без записи файлов.

Опциональная загрузка отсутствующих закреплённых данных и отдельный каталог результата:

```bash
python3 tools/motion/prepare_reference_motions.py --fetch --out-dir tmp/motion-reproduced
```

Загрузчик получает только BVH-данные по закреплённым HTTPS URL и сверяет размер/SHA256 до сохранения. Сторонний код не загружается и не запускается. Без `--fetch` сетевых запросов нет. Повреждённый существующий исходник вызывает ошибку и не заменяется автоматически.

`tools/motion/source-manifest.json` содержит исходные хеши и компактные шаблоны метаданных без массивов кадров. Окна и камера зафиксированы; поиск «лучшего» окна при регенерации не запускается. Все выходные хеши проверяются до первой записи, чтобы изменение парсера не подменяло согласованные референсы незаметно.

## Ограничения и незакрытые вопросы

- Установочный первый кадр BVH не входит в выбранные окна. CMU предупреждает о шуме hand/toe; движения finger/thumb фактически не захватывались.
- Приведение петли не решает контакты стоп, скольжение, проскальзывание одежды или пальцы. Исходная покадровая интерполяция сохраняет шум и изломы скорости; C1-сертификация не заявлена.
- Проекционные камеры выбраны численной эвристикой и просмотрены на манекене. Они не заменяют художественную настройку ракурса/поз для ведьмы.
- При переносе в2D нужны отдельные поправки перспективного укорочения, локтей, кистей, порядка перекрытия, ткани и суставов. В49_12 проекции предплечья местами сокращаются примерно до26–27% пространственной длины; ограничение масштаба снизу искусственно изменяет такие позы и требует просмотра.
- Эти JSON не являются нативными `.spine`, готовыми Spine Runtime-экспортами или подтверждением лицензии редактора/runtime. Нативный импорт/экспорт и художественная приёмка остаются отдельными проверками.
