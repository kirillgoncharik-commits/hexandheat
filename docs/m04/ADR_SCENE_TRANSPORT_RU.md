# ADR M04-01 — transport и completion barriers

Статус: implemented for review, 01.11.2026. Parent: Issue #20.

Сохраняем DOM/CSS и вводим один `SceneTransport` на rAF. Его активное время управляет функциями progress → конечный стиль. Renderer Promise завершается после update(1). Это небольшой собственный tween adapter; отдельная библиотека и WAAPI не потребовались. Решение отклоняется от предложенного WAAPI-кандидата в допустимых границах spike: проще проверить паузы, отмену и точный final commit, без зависимости от finished у paused animation.

`CueDirector` ожидает required participants, ограничивает срок длительностью +1000ms активного времени; при редких кадрах запас адаптируется до трёх наблюдаемых кадров, с верхней границей 3000ms, отменяет старые round scopes и записывает trace. Deadline тоже замораживается на hide. Ошибка renderer приводит к точному статичному виду доверенного события; неизвестные domain events по-прежнему отклоняются валидатором. Финансовый lifecycle не выводится из анимации.

Body controller получает priority 0, raster player — 2, tweens — 10, aura — 20. Все видят один timestamp кадра. Логические стыки остаются на 4000ms grid. Поздний render callback может применить переход, пока видна первая общая нейтральная поза растра, phase [0,1000ms), и предыдущее состояние уже было показано не менее 4000ms активного времени. Если jitter ещё не дал полные 4000ms, проверка повторяется в том же нейтральном окне, не теряя целый следующий оборот. В более поздней позе переход откладывается и пишется missedSeam. Это обработка пропущенного кадра, а не разрешение обрезать цикл. Фаза кадров и музыкальная сетка не сбрасываются. Для будущего плотного Spine runtime нужна своя marker-confirmed seam policy; секундное окно не переносится в него автоматически.

Для колонок сохраняем существующие nodes, когда authoritative target имеет правильный suffix выживших символов. Некоторые старые sample boards этому не соответствуют: тогда column получает новые nodes и точный target, а trace пишет board.reconcile. Это ограничение fixtures, а не утверждение о корректности production tumble.

Окна имеют отдельный transition owner и generation, используют то же активное время, но не приостанавливают раунд автоматически: поле может завершаться за dimmed modal. Focus, input и duck согласованы. Native modal обеспечивает focus trap; менеджер обрабатывает устаревшие open/close callbacks.

Музыка использует scene → performance → audio mapping при доступном output timestamp, иначе приблизительный mapping. Текущий звук всё ещё синтезированный oscillator POC. Он подтверждает расписание/ownership, но не sample-aligned musical stems или физическую AV latency. One-shots удаляются на hide/new round и не воспроизводятся задним числом после mute.

Альтернативы: GSAP — полезен при усложнении партитур; Pixi/Spine — при готовности production renderer/rig. Ни один из них не отменяет необходимость этого event/barrier/ownership контракта.

Remove/fall используют абсолютные anchors внутри одной партитуры: поздний кадр не добавляет новую полную задержку каждому подэтапу. Read hold начинается после фактического commit точного числа, поэтому пропущенные кадры count-up не съедают время чтения. В первом browser trace iframe обновлялся примерно раз в секунду; это вызвало два безопасных cascade fallback в раннем прогоне. После коррекции anchors/deadline выполняется повторный browser trace. Это наблюдение окружения, а не заявленная производительность на пользовательских устройствах.
