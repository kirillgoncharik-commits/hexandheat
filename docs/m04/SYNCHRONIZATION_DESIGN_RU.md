# M04.1 — синхронизация поля, окон, ведьмы и звука

Дата: 01.11.2026. Статус: **предлагаемый контракт, реализация ещё не выполнена**. Основание: [скоуп](MILESTONE_SCOPE_RU.md), [исследование и аудит](RESEARCH_PRIMARY_SOURCES_RU.md). Этот документ уточняет timing для следующей реализации; старые video-предложения и длительности 3.6/4.2/4.8 секунды из DOC-10 не применяются к новой растровой сцене.

## 1. Что должен чувствовать игрок

У каждого события один смысловой центр: выигравшие символы → сумма; Potion → котёл и изменение multiplier; финал → итог и празднование; окно → перенос внимания и новое действие. Мы синхронизируем **причину, акцент и завершение**, сохраняя осмысленные сдвиги между ними.

Есть два временных слоя:

1. **Отклик события**: кнопка, подсветка, числа, impact/SFX, короткая аура. Запускается без ожидания такта или смены танца.
2. **Ритм сцены**: непрерывная ведьма, музыкальные слои, дыхание света. Имеет общую фазу и разрешённые границы перехода.

Игрок не ждёт окончания танца, чтобы сделать следующий разрешённый Spin. При этом ведьма не перескакивает между состояниями на каждом каскаде.

## 2. Компоненты и границы ответственности

| Компонент | Владеет | Не имеет права |
|---|---|---|
| Outcome/domain reducer | Проверенными данными и последовательностью событий | Зависеть от FPS, аудио или случайности эффектов |
| RoundCoordinator | Ставкой, session, play/end/resume, финансовым статусом | Считать callback танца основанием списать или выплатить средства |
| SceneTransport | Монотонным presentation time, epoch, фазой, pause/resume | Брать длительность цикла из скорости сети или количества кадров |
| CueDirector | Партитурой события, barriers, scopes, отменой, deadlines | Менять payout и пропускать непоказанные обязательные данные без fallback |
| Board/Counter/FX players | Отображением полученных данных, marker/completion | Генерировать новые игровые результаты |
| WitchPlayer + reaction policy | Body entry, фазой кадров и декоративными слоями | Блокировать финансовое завершение/новый раунд ради полного цикла |
| ModalManager | Единственным активным модальным фокусом, входом/выходом | Открывать конкурирующие окна или запускать Spin под окном |
| SceneMood + AudioClockAdapter | Общей интенсивностью, музыкальной фазой, one-shots | Переопределять tier по другой таблице или играть старый impact нового раунда |

Поток: validate outcome → domain event → CuePlan → prepare → согласованный start → required completion + read hold → следующий event. Декоративный loop работает рядом и не входит в required barrier. Финансовый coordinator сохраняет свой проверенный контракт; presentation refactor не должен его переписывать.

Нужно различать `RESULT_KNOWN`, `PRESENTATION_COMPLETE`, `FINANCIALLY_SETTLED`, `CELEBRATION_RELEASED`. Это разные состояния, а не четыре названия одного `finally`. Их порядок зависит от платформенного контракта: визуальный код не объявляет settlement успешным. Доступность Spin требует корректного финансового и обязательного presentation status, но не CELEBRATION_RELEASED.

## 3. Время и общий ритм

SceneTransport считает активные миллисекунды от монотонной performance timeline с учётом явных пауз. Все visual players получают **один snapshot времени на кадр**. Unit contract: presentation — ms, Web Audio — seconds; преобразование только в AudioClockAdapter.

Границы body вычисляются как `epoch + n × 4000`, а не как «ещё 4000 мс после фактического прихода прошлого callback». Кадр растрового состояния: `floor(phaseMs / 1000)`, где `phaseMs` в диапазоне [0, 4000). Controller и RasterWitchPlayer используют один epoch/phase, а `switchTo` не создаёт собственное начало отсчёта.

При foreground-jank время не замедляется скрытым clamp: renderer показывает актуальную фазу, пропуская недоступные промежуточные кадры; markers учитываются ровно один раз. Крупная остановка обрабатывается отдельной late-cue политикой. Нельзя проигрывать накопившиеся звуки пачкой.

Для spike предлагается 120 BPM, 4/4:

| Единица | Время | Применение |
|---|---:|---|
| Beat | 500 мс | Допустимая граница смены музыкального слоя |
| Bar | 2000 мс | Музыкальная фраза и переходы, где ожидание не мешает UI |
| Body loop / 2 bars | 4000 мс | Обязательная длина всех 5 состояний ведьмы |
| Один PNG | 1000 мс / 2 beats | Четыре черновые позы в текущем растровом loop |

Это гипотеза композиции. Не квантовать на beat ввод, показ ошибки и необходимую информацию о результате. Тела не ускоряются в Fast, аудио не меняет pitch. Разные режимы меняют партитуры поля, а не глобальный scale всего приложения.

Default реализации для DOM: один rAF transport и небольшой adapter для WAAPI. При управлении `.currentTime` у приостановленных анимаций adapter сам подтверждает конечный commit и завершает свой Promise; нельзя без проверки ждать браузерный `finished` у бесконечно paused animation. При самостоятельном playback дочерняя animation обязана следовать transport start/pause/resume и сообщать фактическое завершение. Выбор фиксируется в ADR после spike. Неконтролируемые CSS infinite animations для связанных смысловых акцентов убрать или перевести на общую фазу.

## 4. Контракт CuePlan

У каждого плана: version, eventIndex, presentationRoundId, cueId, transportEpoch, required/decorative, owner scope, prepare dependencies, start anchor, markers, duration/readHold, completion, cancellation и fallback. IDs предназначены для диагностики представления, без session tokens.

| Этап | Требование |
|---|---|
| Prepare | Проверить данные, позиции и наличие renderer; дождаться decode critical assets либо выбрать известный fallback |
| Start | Назначить общий anchor; относительные labels задают задержки, а не локальные `setTimeout` каждого компонента |
| Impact | Поле, котёл, свет и SFX получают один marker ID; дубли отсеиваются по cue/epoch/marker |
| Readable | Не скрывать число до минимальной выдержки; current cascade, round total и final — разные поля |
| Complete | Дождаться всех зарегистрированных required participants и read hold; отсутствие обязательного участника — ошибка, не пустой успешный Promise.all |
| Timeout / cancel | Завершить контракт ровно один раз, снять listeners/handles, восстановить известное состояние; записать причину |

Completion barrier подтверждает конечные позиции/значения renderer, а не только прохождение расчётной длительности. Deadline = заданная длительность + configurable budget; стартовая гипотеза для budget 1000 мс активного времени. Hide не расходует этот budget. При зависании игрок получает конечный статичный вид события; продолжение разрешено только если данные доверенные и финансовый coordinator допускает его. Неизвестный outcome/settlement требует recovery, а не фиктивного успешного завершения.

Event порядок сохраняется из book. Параллельны только локальные участники одного этапа. Выбор декоративных вариантов детерминируется book/event/asset version и не использует игровой RNG. Replay повторяет данные и порядок; frame-identical запись на любом железе не требуется.

## 5. Партитура поля и Potion

BoardRenderer сохраняет объекты символов между событиями. Координаты и соответствие исходного/следующего board задаются данными события; renderer не разыгрывает случайное поле для красивого падения. Для одинаковых символов в разных клетках нужны устойчивые instance IDs.

Пример Normal-партитуры, **если book уже задаёт порядок win → Potion → cascade**. Это motion-гипотеза, не новое правило расчёта. Если порядок событий другой, сохраняем его.

| Относительное время | Поле / числа | FX / звук | Ведьма |
|---:|---|---|---|
| 0 мс | Старт highlight выигравших клеток | Короткий win accent на общем marker | Запрос tier с владельцем текущего раунда; тело продолжает loop |
| 140–350 мс | Exact award становится читаемым; count-up приходит в точное значение | Свет поддерживает акцент без новых stings | Допустима независимая аура |
| До 550 мс | Выдержка для чтения | Спад краткого FX | Без сброса на IDLE |
| 600 мс / `potion.impact` | Число multiplier меняется из event.from в event.to | Всплеск котла, свет и Potion SFX одним marker | Локальный magic accent; **не BONUS** |
| 600–850 мс | Читаемый multiplier | FX затухает | Текущий body loop |
| 900–1050 мс | Remove только указанных выигравших символов | Короткий dissolve | Текущий body loop |
| 1050–1400 мс | Fall/refill с контролируемым stagger, затем фактический settle | Landing accent по settle marker | Смена tier только на ближайшей глобальной границе 4000 мс |
| После completion | Следующее событие | Нет оставшихся обязательных FX | Loop не задерживает переход |

Значения дополняются motion tokens: button feedback 80–100 мс; highlight 140 мс; modal enter 220 мс / exit 160 мс; column stagger 25–40 мс; numeric read hold ориентировочно 450 мс Normal / 250 мс Fast. Дизайнер проверяет реальную читаемость, особенно sub-cent и больших сумм. Одинаковая роль использует одинаковую easing family; цифры и основной board не имеют overshoot, мешающего чтению.

Длительность count-up может ограничиваться по tier, но его последний кадр всегда содержит точное авторитетное значение. Skip доводит число и board до правильного финального вида; не пересчитывает payout.

## 6. Ведьма: полный цикл, слои и владение реакциями

Состояния: IDLE, SMALL_WIN, MEDIUM_WIN, BIG_WIN, BONUS. Приоритет внутри одного раунда: BONUS > BIG > MEDIUM > SMALL > IDLE. Текущие пороги 4×/10× — prototype configuration; синхронизация не делает их утверждённой production-механикой.

- Track/body 0: защищённый цикл 4000 мс, переход только на seam. Любой начатый non-idle играет полностью, даже после settlement.
- Accent: независимый краткий эффект света/котла/ауры; не перезапускает body и не создаёт новое финансовое событие.
- Pending: не бесконечная очередь танцев, а сильнейший актуальный запрос текущего раунда с cue/round ownership.
- Новый раунд удаляет **не начатые** запросы предыдущего. Уже идущий body завершает свой цикл. Старая очередь не должна внезапно запускать BIG_WIN над новым проигрышем.
- После окончания раунда pending может стартовать на ближайшем seam, пока нового раунда нет. После одного полного celebration loop — IDLE, если нет нового актуального запроса.
- Cascade/reveal не сбрасывает body. Potion не вызывает BONUS. BONUS возможен только от настоящего bonus state либо явно обозначенного motion fixture.

Перед началом нового body entry проверяется готовность ассетов. Если они не готовы к seam, продолжается корректный IDLE, немедленные FX уже дали обратную связь; фиксируется `degraded/missedSeam`, а не обещается реакция ≤4 с. Critical preload должен сделать такой случай исключением. Decode failure переводит в проверенный static fallback без deadlock.

При растровой базе: общий pivot, размер, scale, силуэт и совместимые neutral poses. Opacity crossfade около 180 мс — настраиваемый способ скрыть стык, а не интерполяция тела. Четыре сильно отличающиеся картинки не станут плавной анимацией от правильных часов. Paintover и просмотр всех 25 пар обязательны; если этого недостаточно, нужны дополнительные in-between кадры или настоящий rig отдельным решением.

Будущий Spine adapter: body на track 0, частичные expression/magic tracks не конфликтуют по keyed bones. AnimationState обновляется от нашего transport. `Complete` используется с учётом loop/entry, `End` — для cleanup; `seam`/`impact`/`accentEnd` привязаны к конкретному entry и dedupe key. Mixing не должен повторно запускать звук из уходящего track. Editor/export/runtime versions фиксируются совместимым набором. Простое `setAnimation` посреди цикла правило M03 не выполняет.

### Неустранимый без продуктового решения компромисс

При rapid Spin игрок может видеть хвост уже начатого победного танца на следующем loss. Предлагаемая политика: не запускать старые pending реакции, убрать связанные с прошлым раундом текст/impact, сохранить начатое тело фоновым и направить внимание на новый board. Музыка текущего раунда может перейти в нейтральный слой на ближайшем beat; короткий хвост тела сам по себе не означает новый выигрыш.

Это нужно показать на UX-review, а не объявлять решённым архитектурой. Если игроки продолжают путать исходы, Gate M04.1 не пройден по восприятию. В отдельное решение PO выносится изменение body-политики, например дополнительные artist-authored anchor points. Ни задержка нового Spin на 4 с, ни обрезание активного цикла не вводятся скрыто.

## 7. Окна и приоритет внимания

ModalManager использует состояния CLOSED → PREPARING → OPENING → OPEN → CLOSING. В норме одно модальное окно; смена содержимого не оставляет два backdrop или два focus trap. Вход объединяет backdrop/dim, panel motion и audio duck через общий marker; focus передаётся после готовности содержимого. Закрытие симметрично возвращает focus исходной кнопке, если она существует.

| Тип | Когда показывать | Поведение сцены |
|---|---|---|
| Settings/rules/paytable | Оболочка отвечает на click сразу; во время обязательного движения показ полного содержимого на ближайшей безопасной границе | При необходимости приостановить presentation; не network/settlement. Есть видимый feedback ожидания |
| Big/max win | После точного final counter и нужного barrier | Один результат, один impact; не дублировать те же числа вторым конкурирующим overlay |
| Bonus intro/retrigger/summary | По порядку авторитетных bonus events | Продолжение зависит от intro/read/continue, body остаётся декоративным |
| Network/session/restriction | Сразу, без ожидания beat/seam | Корректность и recovery выше зрелищности; финансовые запреты сохраняются |

Приоритет: системная ошибка/ограничение → обязательное feature window → result window → справочное окно → ambience. Более высокий приоритет приостанавливает или завершает нижний по заданной политике, а не просто накладывается сверху.

Повторное open/close и close во время opening обрабатываются одним актуальным transition generation. Быстрый повтор не вызывает старый onComplete, не возвращает focus под новым окном и не оставляет input lock. Escape действует по правилам конкретного окна; обязательный bonus/recovery экран не становится dismissible случайно. Space/Enter не проваливается в Spin. Reduced Motion сохраняет dim/focus/readability, убирая scale/slide/shake.

## 8. Звук и настроение

У сцены единая таблица tier → mood → FX intensity. Порог ENERGY не должен вычисляться независимо от win tier. Временные осцилляторы остаются только инструментом теста. Поставка финального звука требует оригинальных stems/SFX и provenance.

AudioClockAdapter поддерживает соответствие scene time ↔ performance time ↔ audio output time. При наличии `getOutputTimestamp()` использует его пару времён, при отсутствии — маркированную приблизительную оценку и отдельный device test. Не полагается на точное равенство `audioContext.currentTime` и `performance.now()`.

Музыка запускает синхронные stems с одинаковыми sample rate, loop length и phase offset. Предлагаемый lookahead 25 мс / schedule horizon 100 мс проверяется под нагрузкой; это настройки spike. UI impact, известный прямо сейчас, использует минимальный безопасный lead, а не добавляет 100 мс обязательного ожидания каждому click. На уже пропущенный marker звук не догоняется поздним ударом.

Смена stem обычно на следующем beat, максимум около 500 мс при 120 BPM; длинная фразовая смена допустима только для background. Input/error/числа этого не ждут. Impact SFX планируется на момент воздействия, а не «на следующий beat» независимо от поля. Если main thread опоздал настолько, что marker уже нельзя согласовать, применяется late-cue policy: сохранить точные данные, пропустить устаревший one-shot, записать сбой.

Mood сохраняется до своего release marker, а не до завершения `playOutcome`/сетевого `finally`. Новый раунд, обязательное окно или ошибка могут дать новое решение mood; декоративный танец прошлого раунда не удерживает HOT поверх чужого loss. Для каждого такого перехода задан короткий gain ramp и cancellation прежней автоматизации; не брать устаревшее значение gain как начало новой кривой.

Mute меняет gain, не фазу. Unmute возвращает актуальный слой, не очередь старых stings. AudioContext возобновляется после допустимого user gesture; отказ или suspend не блокирует игру. Смена output route требует новой оценки clock mapping. Bluetooth latency измеряется отдельно.

## 9. Cancel, visibility, Fast и Reduced Motion

Scopes разделены: round (числа/FX/impact), modal transition, scene ambience и protected body entry. Новый round отменяет старые round cues, но не обрывает защищённое тело. Scene teardown освобождает все ресурсы; обычный закрытый раунд не равен teardown.

| Ситуация | Обязательная политика |
|---|---|
| Tab hidden / lifecycle suspend | Заморозить presentation transport и body phase, остановить/приглушить scheduled audio. Сеть/settlement продолжают свой контракт независимо |
| Возврат | Проверить round state, восстановить актуальный event/fallback, заново связать часы и музыкальную фазу; до нового Spin получить корректный статус. Не проигрывать накопленный backlog |
| Main-thread stall | Отрисовать актуальный прогресс; не считать все пропущенные callback обязательными звуками; trace lateness |
| Fast | Короткие отдельные партитуры и read minima; body по-прежнему 4000 мс, без ускорения музыки |
| Replay | Та же domain sequence и cue mapping; повторы сбрасывают round generation, не ставят новую ставку |
| Reduced Motion | Статичная согласованная поза, числа/подсветка/объяснения сохраняются; логический цикл и callbacks продолжают корректно завершаться |
| Ошибка ассета | Static fallback, точное число/board, отсутствие бесконечного loading; renderer completion ограничен |
| Ошибка схемы / неизвестные средства | Recovery и запрет опасного повторного play; анимационный timeout не снимает финансовый запрет |

## 10. Проверка и измерения

| Проверка | Метод / ожидаемый результат |
|---|---|
| Общий visual marker | Trace назначенного/фактического marker + запись с frame/cue overlay; связанные появления в одном кадре, максимум один кадр измерительной погрешности на 30 FPS |
| Input feedback | Не менее 100 локальных действий прогретого demo; ≤100 мс p95, RGS время отдельно |
| Audio/visual impact | Trace clock mapping + запись со звуком на встроенном/проводном выходе; цель ≤50 мс p95. Программная оценка не выдаётся за измерение реального динамика |
| Body и фаза | 30-минутный soak на 30/60/120 Hz или доступных экранах; 4000 мс logical loops, без накопленного смещения; отклонения и пропуски кадров отражены |
| 25 переходов | Все 20 разных ordered state pairs + 5 self-loops; state request в начале/середине/перед seam, совпадение поз и правильный приоритет |
| Completion/cancel | Fake clock + renderer stub: success, failed prepare, missing participant, timeout, aborted opening, teardown; каждый cue закрыт один раз, listeners удалены |
