# M04 — единая постановка игрового цикла и подготовка к Stake

Дата: 01.11.2026. Статус: **SCOPE PROPOSED / IMPLEMENTATION NOT STARTED**. Трекер: [Issue #20](https://github.com/kirillgoncharik-commits/hexandheat/issues/20).

## Результат для игрока

Поле, котёл, ведьма, окна и звук воспринимаются как одна сцена: у события есть понятная причина, общий акцент и завершение. Выигрыш сначала становится читаемым, затем символы исчезают и падают новые; звук попадает в момент воздействия; окна не спорят с полем за внимание. Ведьма поддерживает настроение игры, а управление отвечает сразу.

«Синхронно» не означает запускать все элементы одновременно. Подсветка может предшествовать исчезновению, колонки — падать с небольшим сдвигом, а танец — смениться на границе цикла. Эти отношения задаются одной партитурой, а не случайно складываются из локальных таймеров.

Предлагаются две поставки внутри M04. **M04.1 — обязательная первая поставка с отдельной приёмкой синхронизации. M04.2 — сохранённый объём release candidate из предыдущего ТЗ.** Закрытие M04.1 не закрывает Issue #20 и не означает готовность к запуску на Stake. Первая поставка не должна ждать production math, чтобы проверить ощущение сцены на явно обозначенных sample outcomes.

### Решения по ведьме и технологии

Растр остаётся обязательной рабочей базой. Ни видео, ни покупка Spine не являются зависимостью первой поставки. Для качественного будущего Spine сохраняется интерфейс плеера и описываются tracks/markers/export contract; настоящий rig — отдельный результат при наличии художника, совместимого runtime и уже разрешённой лицензии.

Все пять телесных циклов длятся **4000 мс активного времени сцены**, включая IDLE. Смена только на стыке; уже начатый non-idle проходит полный цикл. Ведьма не задерживает settlement и доступность следующего Spin. Немедленный отклик обеспечивают локальные FX, свет, котёл и SFX. При готовых ассетах ожидание смены тела — от 0 до почти 4000 мс. Называть такую смену мгновенной нельзя.

В быстрых последовательных раундах начатый танец может продолжаться поверх следующего результата. Для этого нужны отдельная политика владения реакциями и UX-проверка. Если полные циклы мешают восприятию, потребуется отдельное продуктовое решение о более частых точках перехода; этот скоуп самовольно правило не меняет. Детали: [SYNCHRONIZATION_DESIGN_RU.md](SYNCHRONIZATION_DESIGN_RU.md).

DOM/CSS сохраняется для первого среза; предлагается небольшой timeline adapter на Web Animations API и общем transport. GSAP, Pixi и Spine изучены как источники рабочих паттернов. Миграция всего приложения на другой движок в SYNC-01 не входит. Выбранная реализация фиксируется коротким ADR после spike и обязана пройти одинаковые clock/cancellation тесты.

## Критерии M04.1

Следующие числа — **предлагаемые внутренние цели**, а не требования Stake и не уже измеренные результаты.

- Связанные визуальные акценты одного marker появляются в одном render frame; допуск измерения до одного кадра на 30 FPS. Плановые сдвиги явно записаны в cue sheet.
- Видимый отклик на локальный ввод ≤100 мс p95 в прогретом приложении; ожидание RGS измеряется отдельно.
- Оценочный audio/visual skew для impact ≤50 мс p95 на встроенном/проводном аудио. Bluetooth и неподдержанная точная оценка — отдельные результаты, без обещания универсальных 50 мс.
- Все body loops имеют 4000 мс логической длительности; видимая смена на ближайшем кадре после стыка, без накопления фазового дрейфа за 30 минут.
- Каждый required cue завершён, отменён либо приведён в конечное fallback-состояние ровно один раз. Ошибка декора не оставляет заблокированные кнопки и не меняет финансовый результат.
- Loss, multi-cascade, Potion, win→loss, rapid Spin, big/max, бонусные fixtures, modal interruption, hidden tab, mute и Reduced Motion имеют trace и проверяемый итог.
- Отдельно проходят визуальное ревью стыков и короткое UX-сравнение с M03: игрок понимает причину эффекта и не воспринимает оставшийся танец как новый выигрыш.

Подробная матрица и методика измерений находятся в [дизайне синхронизации](SYNCHRONIZATION_DESIGN_RU.md). Если четырёхкадровый растр остаётся слишком грубым, это фиксируется как ограничение графики; исправная синхронизация не объявляется заменой полноценной анимации.

## Оценка и выдача

Предварительная трудоёмкость M04.1: **8–12 инженерных дней**, **2–4 дня motion/art**, **1–2 дня sound**, **2–3 дня QA**, с возможным пересечением. Spike SYNC-01 занимает первые 1–2 инженерных дня и уточняет оценку. Это объём по ролям, не обещание календаря; состояние веток и доступность исполнителей ещё не согласованы. M04.2 оценивается отдельно после math/session audit; прежнюю оценку нельзя считать уже подтверждённой.

Выдача M04.1: reviewable PR, private motion demo, Figma motion page, cue sheets/tokens, raster exports с provenance, trace/video/device report и актуальный список release blockers. Следующий work task уже подготовлен: [WORK_TASK_M04_1_RU.md](WORK_TASK_M04_1_RU.md). Выдача M04.2 дополнительно требует platform evidence и release archive по исходной архитектуре.

Документы задают скоуп для review. Реализация, новые художественные экспорты, обновление Figma и измерения здесь ещё не выполнены.
